# MVP Live Runtime Completion architecture models

Evidence-backed capability closure for one complete Better Tomorrow live dramatic experience.

**Architecture authority:** A capability is complete only when its production path, runtime behavior, user-visible outcome and durable evidence agree; task documents alone confer no completion.

## Viewpoint map

| Concern | Viewpoint | Model | Decisions |
| --- | --- | --- | --- |
| Player-visible experience as the completion boundary | `context` | [MVP Completion - Experience Context](context/experience-context.md) | D1 |
| Launch, semantics, agency, commit, rendering and evidence must all connect | `component` | [MVP Completion - Capability Chain](components/capability-components.md) | D1, D2 |
| One real turn preserves semantics and evidence to the player surface | `sequence` | [MVP Completion - End-to-End Turn](sequence/end-to-end-turn.md) | D1 |
| Claims require multidimensional proof and explicit residual gaps | `class` | [MVP Completion - Evidence Model](classes/capability-evidence-model.md) | D2 |
| Implementation is not completion until integrated and proven | `state` | [MVP Completion - Capability Lifecycle](states/capability-lifecycle.md) | D2 |

## Drift focus

Many historical MVP waves declared local completion while later audits found broken handoffs. Models keep capability claims tied to the end-to-end turn and classify evidence maturity.
